# seqera_service_account_secret (Resource)

Issue a client secret for a service account.

The service account exchanges its client ID (`client_id`) and this secret for an access token at `POST /token`. The secret value is returned only when it is issued,
so it is kept in the Terraform state as a sensitive attribute: protect the state accordingly.

Every argument forces a new secret. Destroying the resource revokes the secret; access tokens
already issued with it stay valid until they expire (1 hour by default).

A service account holds at most 2 live secrets. To rotate without downtime, manage one secret per
service account with `create_before_destroy` and trigger replacement with `time_rotating`:
the new secret is issued before the old one is revoked. Managing more than one secret per service
account, or issuing secrets outside Terraform, can fail an apply with a conflict.

A secret that expires or is revoked outside Terraform is removed from the state, so the next plan
issues a new one.

Import is not supported: the secret value cannot be retrieved after it is issued.

## Example Usage

```terraform
resource "seqera_service_account" "jobs" {
  org_id      = var.org_id
  name        = "scheduled-jobs"
  description = "Identity for scheduled jobs"
}

# Rotate the secret every 300 days, well before its 365-day expiry.
resource "time_rotating" "jobs_secret" {
  rotation_days = 300
}

resource "seqera_service_account_secret" "jobs" {
  org_id             = var.org_id
  service_account_id = seqera_service_account.jobs.id
  expiry_days        = 365

  lifecycle {
    # Issue the new secret before revoking the old one, so there is no gap.
    create_before_destroy = true
    replace_triggered_by  = [time_rotating.jobs_secret]
  }
}

# Hand the credentials to the jobs through a secrets manager.
resource "aws_secretsmanager_secret_version" "jobs" {
  secret_id = aws_secretsmanager_secret.jobs.id
  secret_string = jsonencode({
    client_id     = seqera_service_account_secret.jobs.client_id
    client_secret = seqera_service_account_secret.jobs.secret
  })
}
```

## Schema

### Required

- `expiry_days` (Number) Lifetime of the secret in days: 30, 90, 180 or 365. Changing it issues a new secret.
- `org_id` (Number) Organization numeric identifier. Changing it issues a new secret.
- `service_account_id` (Number) Service account numeric identifier (`seqera_service_account.x.id`). Changing it issues a new secret.

### Read-Only

- `client_id` (String) OAuth client ID of the service account, to use with `secret`. Platform creates the client when the first secret is issued, so prefer this attribute over `seqera_service_account.client_credentials.client_id`, which stays null until the next refresh.
- `created_at` (String) When the secret was issued (RFC 3339).
- `expires_at` (String) When the secret expires (RFC 3339). From then on it can no longer be exchanged for an access token.
- `hint` (String) Masked secret showing its last 4 characters, as shown in the Platform UI.
- `id` (Number) Secret numeric identifier.
- `secret` (String, Sensitive) Secret value. Returned by the API only when the secret is issued.
- `status` (String) Status of the secret: `ACTIVE`, or `EXPIRING` when it is close to its expiry date.
