# Design: `seqera_service_account` and `seqera_agent`

- **Date:** 2026-09-28
- **Branch:** `feat/agents-service-accounts`, stacked on #262 (API spec 1.226.2)
- **Status:** approved in conversation, pending written-spec review

## Goal

Let users manage the whole agent setup in Terraform: create a service account,
add it to a workspace, create an agent that runs as that account, and point a
`seqera_action` at the agent.

```
seqera_service_account ──member_id──▶ seqera_workspace_participant (role allows LaunchAgent)
        │ id                                        │ (must exist before the agent)
        ▼                                           ▼
seqera_agent.service_account_id ◀───────────────────┘
        │ id
        ▼
seqera_action.agent.agent_config_id   (response_type = "agent")
```

The mechanical spec update is in #262. This change adds only the overlays,
hand-written data sources, examples and docs on top of it.

## Scope

In scope:

- `seqera_service_account` resource and data source.
- `seqera_agent` resource and data source.

Out of scope, each decided explicitly:

| Item | Why not |
|---|---|
| `seqera_agent_enabled` (enable/disable toggle) | Wait for user demand. `status` is exposed read-only instead. |
| Plural data sources (`seqera_service_accounts`, `seqera_agents`) | Existing data sources are singular lookups by name. |
| `agent_instructions_template_id` | UI analytics only (see Findings). |
| Service-account tokens | The API has no endpoint for them. |
| Agent launch, runs and run status | Runtime operations, not configuration. They stay in the SDK only. |

## Findings that shape the design

All from `~/work/platform` at `055b94cc` (2026-09-22) unless noted.

1. **`serviceAccountId` is the service account's user id**, which is the same
   value as `ServiceAccountDto.id` (`ServiceAccountServiceImpl.toDto` maps
   `user.id`, and `findInOrganization` looks up by user id). So
   `seqera_agent.service_account_id = seqera_service_account.x.id` is correct.
   `memberId` is the org membership id, which `seqera_workspace_participant`
   takes.
2. **Service-account binding is validated when the agent is saved**
   (`AgentIdentityValidator`): the account must be an enabled service account
   of the workspace's org, a participant in the workspace, and hold
   `LaunchAgent` there. Otherwise the save returns 409.
3. **Without a service account, the agent runs as whoever triggers it.**
   - A trigger-driven launch from a `seqera_action` falls back to the action's
     owner (`action.user`, in `AgentActionDispatcher.groovy:180`). For
     Terraform-managed actions, that's the user behind the provider's token.
   - A direct launch (`POST /agents/launch` or the UI) runs as the launching
     user.
   - `AgentServiceImpl.groovy:298` carries
     `FIXME: PLAT-6567: reject the launch when the agent binds no service account`,
     so the fallback is expected to be removed.
4. **Service accounts are intended to be required** (service-accounts spec
   FR-020). The UI enforces this only while the `SERVICE_ACCOUNTS_ENABLED` flag
   is on. The API does not enforce it: the field is `@Nullable` and validation
   returns early on null.
5. **`serviceAccountId` and `githubAppCredentialId` are
   `@Schema(hidden = true)`** in the Platform request DTOs, and have been since
   they were introduced (PLAT-6482, AI-469). They are missing from the platform
   repo's flattened spec, but the cloud.seqera.io 1.226.2 spec we vendor
   includes them. Both are behind UI feature flags.
6. **`agentInstructionsTemplateId` never supplies instructions.**
   - Templates are a hardcoded UI list (`AGENT_TEMPLATES`) that pre-fills the
     form.
   - The architecture doc describes the id as "optional source template id for
     analytics/edit context".
   - The API requires non-empty `agentInstructions` on every create and update,
     and launches use only `agentInstructions`.
7. **Deleting or disabling an agent pauses every action that targets it**
   (`DeactivatedAgentActionPauser`).
8. **When a service account leaves a workspace, its bound agents are disabled**
   on a best-effort basis (`AgentServiceAccountBindingCleaner`). This includes
   deleting the account from the org.
9. **A deleted agent is a tombstone, but reads as 404**
   (`AgentServiceImpl.groovy:81`). Repeat deletes are harmless.
10. **Backend limits:**
    - agent name: `^[A-Za-z0-9_-]+$`, at most 255 characters, unique per
      workspace
    - description: at most 120 characters
    - instructions: at most 50,000 characters
    - service-account name: 1–40 characters, unique across the platform; the
      platform's own data-model doc says 100, but the served spec says 40
    - service-account description: at most 1,000 characters

## Approach

Follow the existing split, the one `seqera_custom_role` and `seqera_team` use:

- **Resources are generated by Speakeasy** from new overlay files. Each
  operation carries `terraform-datasource: null`, so Speakeasy doesn't generate
  its own data sources.
- **Data sources are hand-written** lookup-by-name packages under
  `internal/seqera/`, registered through `terraform.additionalDataSources` in
  `.speakeasy/gen.yaml`.

Hand-writing the resources as well, the `workspace_participant` route, was
rejected: both APIs are plain CRUD with nothing that needs custom logic.

Neither resource sets `x-speakeasy-entity-version`, so both stay at version 0
with no state upgrader. There is no older state to migrate, and
`STATE_UPGRADER_GUIDE.md` says to bump the version only for breaking changes.
`seqera_slurm_ce` (#230) is the precedent.

## Component 1: `seqera_service_account`

**Overlay:** `overlays/service-accounts.yaml`, listed in `.speakeasy/workflow.yaml`.

| Op | Endpoint | `terraform-resource` |
|---|---|---|
| create | `POST /orgs/{orgId}/service-accounts` (201) | `ServiceAccount#create` |
| read | `GET /orgs/{orgId}/service-accounts/{saId}` | `ServiceAccount#read` |
| update | `PATCH /orgs/{orgId}/service-accounts/{saId}` | `ServiceAccount#update` |
| delete | `DELETE /orgs/{orgId}/service-accounts/{saId}` (204) | `ServiceAccount#delete` |

- Entity is bound to `ServiceAccountDto`, with `x-speakeasy-terraform-resource-name: service_account`.
- The `serviceAccount` wrapper is unwrapped from the create, read and update responses.
- `saId` is matched to `id` with `x-speakeasy-match`.
- `orgId` is required and forces replacement on every operation.

**Schema:**

| Attribute | Kind | Notes |
|---|---|---|
| `org_id` | required, forces replacement | |
| `name` | required, updates in place | 1–40 characters (validator from `minLength`/`maxLength`). The description says names are unique across the platform, not just the org, and that a clash fails the apply with a 409. |
| `description` | optional, updates in place | Up to 1,000 characters. |
| `id` | computed | The service account's user id. The description says this is the value `seqera_agent.service_account_id` expects. |
| `member_id` | computed | Org membership id. The description says this is the value `seqera_workspace_participant.member_id` expects. |
| `created_at` | computed | |

**Import:** Speakeasy JSON id `{"org_id": <int>, "id": <int>}`.

**Documented behaviour:** deleting a service account removes it from every
workspace. The platform then disables the agents bound to it and pauses the
actions targeting those agents. None of this shows up in a Terraform plan.

## Component 2: `seqera_agent`

**Overlay:** `overlays/agents.yaml`, listed in `.speakeasy/workflow.yaml`.

| Op | Endpoint | `terraform-resource` |
|---|---|---|
| create | `POST /agents?workspaceId` | `Agent#create` |
| read | `GET /agents/{agentId}?workspaceId` | `Agent#read` |
| update | `PUT /agents/{agentId}?workspaceId` | `Agent#update` |
| delete | `DELETE /agents/{agentId}?workspaceId` (204) | `Agent#delete` |

- Entity is bound to `AgentDbDto`, with `x-speakeasy-terraform-resource-name: agent`.
- The `agent` wrapper is unwrapped from the responses.
- `agentId` is matched to `id`.
- `workspaceId` is made required and forces replacement on all four operations, as in `labels.yaml`.
- The other agent endpoints (`ListAgents`, `LaunchAgent`, `ListAgentRuns`, `GetAgentRunStatus`, `EnableAgent`, `DisableAgent`) are not annotated.

**Arguments:**

| Attribute | Kind | Notes |
|---|---|---|
| `workspace_id` | required, forces replacement | |
| `name` | required, updates in place | The overlay adds `pattern: ^[A-Za-z0-9_-]+$` and `maxLength: 255`, so validators run at plan time. The description says names are unique per workspace. |
| `agent_instructions` | required, updates in place | The overlay adds `minLength: 1` and `maxLength: 50000`. |
| `description` | optional | The overlay adds `maxLength: 120`. |
| `service_account_id` | optional | See the description text below. |
| `github_app_credential_id` | optional | Takes `seqera_github_app_credential.x.id`. The description says it only works when GitHub App credentials are enabled on the Platform instance. |

**`service_account_id` description** (it must say all of the following):

- It takes `seqera_service_account.x.id` and is the identity the agent runs as.
- **When unset, the agent runs with the identity of whoever triggers it.** For
  a `seqera_action`, that's the action's owner, which for Terraform-managed
  actions is the user behind the provider's token. For a direct launch, it's the
  launching user.
- Seqera intends every agent to have a service account. The UI already requires
  one when service accounts are enabled, and a future Platform release is
  expected to reject launches of agents without one. Set it wherever service
  accounts are available.
- When set, the account must be a participant in the workspace with a role that
  allows `LaunchAgent`, or the apply fails with a 409. Configure the
  participant first, either by reference or with `depends_on`.
- It's only available when service accounts are enabled on the Platform
  instance.
- Removing it from the configuration unbinds the account on the next apply.

`service_account_id` stays optional because the API accepts null. Service
accounts are off by default, and are hidden from the platform's own spec, so on
many installs a required field would make agents impossible to create. Moving
from optional to required later is a breaking change, whereas loosening a
required field is not, so we start at the loose end. If the backend starts
enforcing it, users get a 400 and we tighten the schema then.

**Read-only attributes:**

| Attribute | Notes |
|---|---|
| `id` | String. This is the value `seqera_action.agent.agent_config_id` expects. |
| `status` | `active` / `inactive`. Uses `x-speakeasy-param-suppress-computed-diff`. The description says it can change outside Terraform (through the UI, or automatically when the bound service account leaves the workspace), and that updates don't change it. |
| `service_account_name` | |
| `date_created`, `last_updated` | |

**Removed through the overlay:** `agentInstructionsTemplateId` (from requests
and `AgentDbDto`), plus `createdBy`, `createdByUserName` and `updatedBy`.

**Import:** Speakeasy JSON id `{"workspace_id": <int>, "id": "<string>"}`.

**Documented behaviour:**

- Delete is a tombstone. Afterwards describe returns 404, so the resource drops
  out of state cleanly.
- The platform pauses every action that targets a deleted agent. Actions that
  reference the agent are destroyed first anyway, because Terraform follows the
  dependency.

**Behaviour to verify in the generated code:** a `PUT` with
`service_account_id` unset has to reach the server as null or absent. The
backend treats both as "unbind", because the Platform DTO defaults missing to
null and forwards it explicitly.

## Component 3: data sources

Both data sources:

- are hand-written with `terraform-plugin-framework`
- use `common.ConfigureClient`, `common.AddUnexpectedStatus` and `common.PaginatedSearch` (pages of 100, stops based on `totalSize`)
- are registered in `gen.yaml` `additionalDataSources`
- are listed in `.genignore`
- return an error when nothing matches, never an empty result

### `seqera_service_account` (`internal/seqera/service_account_data/`)

- **Inputs:** `org_id` (required) and `name` (required).
- **Lookup:** `ServiceAccounts.ListServiceAccounts(orgId, max, offset)` page by
  page, matching `name` exactly. The endpoint has no name filter.
- **Outputs:** `id`, `member_id`, `description`, `created_at`.
- **Not found:** `Service Account Not Found` / `No service account named "<name>" in org <org_id>.`

### `seqera_agent` (`internal/seqera/agent_data/`)

- **Inputs:** `workspace_id` (required) and `name` (required).
- **Lookup:** `Agents.ListAgents(workspaceId, search=name, max, offset)` page by
  page, still matching `name` exactly, because `search` also returns partial
  matches. Deleted agents are already left out by the endpoint.
- **Outputs:** `id`, `status`, `description`, `agent_instructions`,
  `service_account_id`, `service_account_name`, `github_app_credential_id`,
  `date_created`, `last_updated`.
- **Not found:** `Agent Not Found` / `No agent named "<name>" in workspace <workspace_id>.`

### Tests

Each data source gets a table-driven unit test against an `httptest` server,
using a real `sdk.Seqera` client pointed at it. Cases:

1. match on the first page
2. match on the second page (checks paging)
3. partial-match decoy returned by `search`, e.g. `ci-nightly` for `ci` (agent)
4. not found
5. a response other than 200

Each package factors the lookup into an unexported
`find(ctx, client, scopeID, name)` function that returns the match, `nil` when
none matches, or an error. `Read` calls it and maps the result into state. The
tests call `find` directly against the `httptest`-backed client, so they don't
need framework request or response plumbing.

## Risks

- **Hidden fields.** `service_account_id` and `github_app_credential_id` rely on
  fields Platform hides from its own spec. They could change without the spec
  showing it. Mitigation: they're documented as feature-dependent, and each
  spec update is reviewed with `SPEC_UPDATE_RUNBOOK.md`.
- **Identity fallback removal (PLAT-6567).** Agents without a service account
  will stop launching once Platform removes the fallback. Mitigation: the
  attribute description and the changelog both warn about it.
- **Drift on `status`.** It changes outside Terraform by design. Mitigation:
  it's read-only and documented, with no toggle to fight over.
